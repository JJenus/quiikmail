# AGENTS.md

QuiikMail - a Nuxt 4 email client with a full Nitro backend (Resend → Postgres). Local mock data is gone: the UI talks to the real API.

## Commands

- Use **pnpm**, not npm (CI + `packageManager: pnpm@11.20.0`; README's `npm install` is stale). Do not touch `package-lock.json`.
- `pnpm dev` - dev server at http://localhost:3000 (needs a running Postgres - see `.env`)
- `pnpm db:push` / `pnpm db:studio` - Drizzle schema sync / studio
- `pnpm lint` / `pnpm typecheck` - the only checks; there is **no test suite**. `pnpm build` also verifies the compiled output.

## Gotchas

- `.nuxt/` is gitignored but generated by the `postinstall` (`nuxt prepare`). `tsconfig.json` and `eslint.config.mjs` both import from `.nuxt/`, so lint/typecheck fail until `pnpm install` (or `pnpm exec nuxt prepare`) has run.
- **Nuxt 4 layout**: all client source lives under `app/` (pages, components, composables, services, types, middleware). `~` resolves to `app/`. The backend lives under `server/` (Nitro: routes, middleware, plugins, core, modules, schemas) with the drizzle schema in `server/schemas/`.
- `useMailStore` is a **module-level `reactive()` singleton** (`app/composables/useMailStore.ts`) - never create state inside the composable function body. It also owns `setupOpen`, `mailboxes`, `activeMailboxId` (persisted in localStorage key `quiikmail-mailbox`), `counts`, and the compose state.
- Client data layer: `app/services/{authService,mailboxService,mailService}.ts` call the API with `$fetch`; `MailService` and its methods (extended with `mailboxId`) are the agreed API contract - implement against it, don't change its shape casually. There is **no `$mail` plugin** (removed); the store instantiates `createMailService()` directly.
- **Session auth**: `nuxt-auth-utils`. Server utils (`requireUserSession`, `setUserSession`, `hashPassword`, …) are **Nitro auto-imports - never `import` them from 'nuxt-auth-utils'**. The `#auth-utils` module augmentation lives in `app/types/auth.d.ts` (must be inside the TS program - `server/types/` is not included). The session is fetched by an `enforce: 'pre'` SSR plugin, so route middleware can read `useUserSession()` synchronously.
- **Route middleware**: `useUserSession().loggedIn` is a **ref** - always read `.value` in middleware conditions (`app/middleware/auth.ts` + `guest.ts`); `if (session.loggedIn)` is always truthy and silently breaks every redirect.
- **h3 is pinned to 1.15.11** as an explicit dep, matching nitropack's bundled version. Do NOT add h3@2.x (duplicate `H3Event` type mismatch). Use `import type { H3Event } from 'h3'` for types.
- Nuxt's tsconfig enables `noUncheckedIndexedAccess` - index/array accesses need `!` (e.g. `match[1]!`, `boxes[0]!.id`).
- Nitro `errorHandler` must be a project-relative path (`'./server/error-handler.ts'`, not `~/…`).
- Backend conventions: thin route handlers, service + repository classes, hand-rolled DI (`server/core/container.ts` with `Tokens`), zod v4 validation, consistent error envelope `{ statusCode, code, message, details? }` via `appError()`/`parseZodError` (422 `VALIDATION_ERROR`), tagged consola loggers, `@types/node` for `node:crypto`.
- Mailbox API keys, webhook secrets and SMTP/IMAP credentials are encrypted at rest (AES-256-GCM, `NUXT_MAIL_ENC_KEY`). The inbound webhook URL is shared by all Resend mailboxes (`${NUXT_MAIL_APP_URL}/api/webhooks/resend`); the route verifies Svix signatures against each mailbox's `whsec_` secret. SMTP mailboxes poll IMAP instead (Nitro cron `imap-sync` in `nitro.scheduledTasks`, every 5 min; same path as the manual "Sync now").
- **Providers**: `mailboxes.provider` is `'resend'` (default) or `'smtp'`. Resend mailboxes need `apiKeyEnc` + optional verified `domain`/webhook; SMTP mailboxes need the `smtp*` columns (required) and optionally `imap*` columns (enable inbound polling). Setup modal + settings branch on provider. `mail.service.send` branches per provider; failures wrap as `RESEND_ERROR` / `SMTP_ERROR` (502), IMAP poll failures as `IMAP_ERROR`.
- **Senders**: sending addresses live in `mailbox_senders` (unique per mailbox+email; `isDefault` picks the compose default). `mailboxes.fromAddress` mirrors the default sender. The mailbox's optional `domain` restricts sender addresses (`assertSenderDomain` → 422). `POST/PATCH/DELETE /api/mailboxes/:id/senders` manage them; `send` accepts optional `from` validated against the senders (`resolveSender`). Compose has a From dropdown (`ComposeState.from`, reset on mailbox switch).
- **Counts**: the mails list response `counts` includes `${folder}_unread` keys plus `starred_unread`/`important_unread`; the sidebar shows unread badges (`SidebarItem` `badge` prop), `useMailStore.unreadCount()` reads the `_unread` keys only (no total fallback - that was the old bug).
- **Filters**: the mails list API accepts `unread`/`withAttachments` boolean query params (zod `enum(['true','false'])` - never `z.coerce.boolean()`, it maps 'false' → true); the repo adds `eq(read,false)` / `exists()` subquery on `attachments`. Client: `state.filter` (`'all' | 'unread' | 'attachments'`, reset in `resetState`), the Filter `USelectMenu` in `MailList.vue` header calls `setFilter()`.
- **Mail body rendering**: `MailDetail.vue` renders `bodyHtml` sanitized via DOMPurify (`app/utils/mailHtml.ts` - client-only, hook forces `target="_blank" rel="noopener noreferrer"` on links, styles images), otherwise the plain-text body is escaped + linkified (same utility). `vue/no-v-html` is disabled in `eslint.config.mjs` because all v-html input is sanitized.
- **IMAP ingest**: `server/modules/smtp/imap.client.ts` (imapflow + mailparser) fetches UNSEEN, parses to `ImapMessage`, ingests via `ingest.service` (dedup key = `imap:<Message-ID>` or sha1 fallback in `resendEmailId`, `mails.source='imap'`), marks seen only after success. IMAP attachments store bytes in `attachments.data` (bytea) and the download route streams them; Resend attachments keep the signed-URL redirect flow.
- "Send from" address (mailbox `fromAddress`/senders, verified on the Resend account) is a **separate concept from the account recovery email** (optional `email` on the user, for future password resets). The setup wizard and register form keep them distinct.
- Dev DB: local Postgres role/db `quiikmail` (password `quiikmail`); `.env` is gitignored (see `.env.example` for keys).

## Style

- **Everything is a Nuxt UI component** (`UButton`, `UInput`, `UModal`, `UDropdownMenu`, `UDashboardGroup`, …). No hand-rolled buttons, inputs, modals, dropdowns, or scroll areas. All components live in `app/components/mail/`; the old `base/` split was removed.
- **Dark mode**: `@nuxtjs/color-mode` (bundled with `@nuxt/ui`, `.dark` class) - `preference: 'system'`, fallback light. Use **semantic tokens** (`bg-default`, `bg-elevated`, `text-default`, `text-muted`, `text-dimmed`, `text-highlighted`, `border-default`, `bg-primary`, `text-inverted`, …) instead of hardcoded slate/violet shades. `UColorModeButton` lives in the topbar.
- The shell is a `UDashboardGroup` inside a relative "card" container (page bg outside the card uses `bg-page-bg dark:bg-page-bg-dark`). Panels need `min-h-0!` to neutralize the base `min-h-svh`. The sidebar uses `unit="px"` + `storage-key="quiikmail-layout"` (fixed 256px, not resizable, but collapsible to a 64px icon rail - `collapsible` + `v-model:collapsed` + `:collapsed-size="64"` on `UDashboardSidebar`, state persisted in the layout cookie). The global topbar (`MailTopBar`) sits **above** the list + detail panels in a `flex flex-col` wrapper - pass panel content through `#body` slots, never the default slot (the panel's default `<slot>` fallback renders header/body/footer only when no default content is given).
- Compose is a **single `UDrawer`** (`app/components/mail/MailCompose.vue`): `direction="bottom"`, `:overlay="false"` `:handle="false"` `:dismissible="false"` `:close="false"`. One dialog instance bound to `state.compose.open` - a full-width bottom sheet on mobile (`h-[88vh]`) and a bottom-right floating window on desktop via responsive content classes (`md:inset-x-auto md:right-6 md:bottom-6 md:w-[540px] md:h-[560px] md:rounded-2xl`, `md:max-h-[calc(100vh-5rem)]`). Header is the dark `bg-inverted` bar (minimize/close `UButton`s via `#actions`); minimized state collapses content to `h-12`. **Never split compose across a UModal + UDrawer pair** - two simultaneous open dialogs fight over the focus trap/scroll lock and intermittently break the page.
- The mailbox setup wizard is `MailSetupModal.vue` (a regular centered `UModal`, 2 steps: details → webhook result with manual `whsec_` save fallback). It auto-opens after `init()` when the account has no mailboxes (store `setupOpen`), and from the topbar's "Add mailbox". There is **no `/setup` page**. It branches on provider (Resend: key validate → verified-domain picker → sender addresses; SMTP: SMTP fields + test-connection + optional IMAP fields).
- ESLint stylistic: `commaDangle: never`, `braceStyle: 1tbs` (set in `nuxt.config.ts`, so don't override in `eslint.config.mjs`). Run `pnpm exec eslint . --fix` for auto-fixable style issues.
- Use the custom palette in `app/assets/css/main.css` (`--color-qm-50`…`--color-qm-900`, primary violet-600 `#7C3AED`, page bg `#EEE9FF` light / `#16122B` dark) instead of ad-hoc colors.
- Icons via `@iconify-json/lucide` + `@iconify-json/simple-icons`.
- Commits follow conventional style (`feat: ...`).
